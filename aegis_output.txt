Short answer: when run as-is (no valid OPENAI_API_KEY, default args) the script will print the sanitized prompt (the preamble was prepended), show that 1 mutation was applied, show a unified diff (original → sanitized), attempt to call the OpenAI Images API (prints a warning to stderr about the placeholder API key), fail, fall back to a text completion (which will also fail with the placeholder/invalid key), and then print the generation output (left as {"skipped": true}) plus an error message and the path to the saved session JSON.

What the session JSON contains
- The script saves a JSON session file (nyx_session_<timestamp>.json) in ./nyx_outputs containing the payload that was printed: keys sanitized_prompt, mutations_applied, diff, changelog (one entry for "prepend:lab_frame"), generation ({"skipped": true}), and an "error" string holding the exception messages raised while attempting API calls.

If you run with --dry-run the script will not call the OpenAI API and therefore:
- You will still see the sanitized prompt, the mutations count (1), and the diff.
- It will print "(dry-run) Skipped generation. Session log: <path>" and no API-related error will appear.

Notes
- Exact error strings and the warning come from your environment and the OpenAI client library; with no valid key you should expect network/auth errors. If you set a valid OPENAI_API_KEY and a usable image model, the script will attempt to save generated images into ./nyx_outputs and the generation block in the session JSON will describe those saved artifacts.
